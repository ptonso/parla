# Starting and attaching to an artifact

## Start one

Run `parla init artifact <name> --modality <m> --audience <a>`. The modality page names the engine, and the audience page must exist, so ask the author which audience when none fits. Then complete the card with the author: the phase (`drafting` or `polishing`), the traits that suit the readership (reader, narrative, visual, pacing; `parla guide list trait` lists the pages; `parla guide list procedure` shows whether the author keeps a procedure about choosing traits for this modality), and the first decisions.

## Derive one from another

An artifact made from another is a copy of its folder with `derived-from: <name>` in its card. Files both versions share, such as an abstract, may be symlinks. Ask the author what differs before editing the copy.

## Translations

An artifact with more than one language lists them in the card: `language: en` and `translations:` mapping a code to a folder (`pt: pt`). Each folder holds a complete second tree with the same entrypoint name, and `parla build` compiles every language. After a change in one language, apply the same change to every other language in the same round, since `translation-parity` reports a file, section, entry or bullet that differs in structure. To add a language, copy the artifact's own tree into the new folder, translate the text, and add the card entry.

## Sources

Inputs live under `parla/sources/` and are read-only for you. A folder generated by code is declared in `parla.toml` under `[links]` and synced with `parla link`, so the artifact always reads the current output. A file made for the artifact goes directly under `sources/`, and `parla check` reports a path that does not exist.

## Tables, formulas and citations

Build a table with `parla tool table`, and a formula with `parla tool formula`. To find a citekey, search the library export that `parla config show` names, by author, title or year; the keys already in use are the `\cite` keys in the artifact. A paper missing from the library gets no invented key: tell the author.

## Propose a structure

When the author asks what should go in, propose a structure: for each part, what it argues and how it hands off to the next, and what you would leave out. Capture the agreed shape in the card's decisions.
