# 2026-10-14

First draft, written from the parla skill spec after the guides and the casebook were ported.

- The skill carries the working method only. Every writing principle reaches the agent through `parla guide show`, so the guides can change without the skill changing.
- The worker edits files directly. The job snapshot gives review and undo, so no patch step exists.
- Learning always passes through the author: cases and principles are written only in the accepted wording.
- The texfy skill's idea-vault instructions (notes, wiring, link markup, lab notes, the three moments) were left behind on purpose. Its polishing and article-level habits moved to `asking.md`, `jobs.md` and the guides.
- Links to the project's specs are replaced by `parla --help` and `parla <command> --help`, because the skill is symlinked into projects where the specs do not exist.

## Second pass, same day

- The agent could not tell stable concepts from loose words (guide, case, learn, distill, decision, ask). `SKILL.md` now opens with what `parla` is, then a glossary table of the system's terms, then a table of the three memories (card, guides, casebook) so the agent gets a feel for what is stored where and how each changes.
- The registry read as a list of suggestions. It is now a table of moments: "read this page before you do this", stated as required at that moment. Each supporting page that depends on a term links back to the glossary.
- The job loop was shortened to five movements with their reasons, because the agent is trusted to run the procedure once it knows the language and where to look.
