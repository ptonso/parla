# 2026-10-18

The skill changed with the lean-prompts redesign (the spec log has the full reasoning).

- The prompt the writer reads shrank to about 1000 words. Checkable rules left the guides and became constraints that run in the suite, so the skill teaches the loop (build, read the report, fix, answer probes) in `suite.md` instead of carrying those rules.
- The agent in the author's session became the captain: it routes topics from the hook table, relays questions, and writes to the memories. One worker per job does the writing. A subagent cannot ask the author, so questions travel through the captain. The reviewer subagent was removed, because the suite plus probes with quoted evidence replace it.
- `learning.md` kept the author's batch protocol (triage toggle, then phrasing) and gained a destination test and the hook. `constraints.md` and `relocating.md` are new. The `slimming` idea became `relocating.md`, because the method also serves a new user who ports old rules.
- The skill avoids linking to the project specs, since it is symlinked into projects where they do not exist; commands are discovered with `--help`.

## Later the same day

- Relocating the author's guides showed that a loop which only appends rules lets a topic grow back past its cap. `distilling.md` now asks four questions on every proposal that touches a topic (dedup, generalize, merge, orchestrate) and uses `guide edit` to revise a rule in place. The author chose atomic rules (an id and one instruction) over one paragraph per topic, because they edit and scale better.
